tag: m0485
title: "M485: Send RS485 Packet"
short_title: Send RS485 Packet
brief: Send a hex-encoded packet on the RS485 bus and report any reply
author: thinkyhead

parent: G-code Commands
group: hosts
since: 2.1.3
requires: RS485_SERIAL_PORT

codes: [ M485 ]

notes: |
  - The data is a string of hex digit pairs, one pair per byte, with no spaces. For example, `M485 0A1B2C` sends three bytes.
  - The data must have an even number of hex digits and can be at most 32 bytes (64 hex digits).
  - Any packet that arrives before the command is sent is read and discarded, and reported as `rs485-unexpected-packet:`.
  - After sending, `M485` waits briefly for a reply. A reply is echoed as `rs485-reply:` followed by its hex bytes. If none arrives, the output is `rs485-timeout` (with `M485_PROTOCOL` 2 or higher) or `rs485-reply: TIMEOUT` (with `M485_PROTOCOL` 1).
  - Errors are reported as `String must contain an even number of bytes.`, `String too long (32 bytes max).`, `Not a hex character: <char>`, or `RS485: Write failed <reason>`, where the reason is `interrupted`, `buffer full`, or `timeout`.
  - `RS485_SERIAL_PORT` selects the serial port. `M485_PROTOCOL` sets the reply format and should match what the device on the bus expects.

examples:

- pre: Send a three-byte packet and wait for the reply
  code: M485 0A1B2C
  post: The output shows `rs485-reply:` and the reply bytes, or a timeout message if nothing came back.

---

`M485` sends a raw packet on the RS485 bus, then waits for a reply. It is a low-level command, and the bytes mean whatever the device on the bus expects, so check that device's protocol documentation before you send anything.
