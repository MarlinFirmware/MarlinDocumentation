# Site Dev Notes

## Lexicon

- Main Menu, Left Sidebar, and Left Nav all refer to the same set of links on the left side of every page.
- Inner Nav, Right Nav, and Page Table of Contents all refer to the section links on the top/right of the page content area.
- Section TOC refers to the links at the bottom of the page that go to the sub-articles of a section.

## Required Patches

- The anchors generated by jekyll-toc using `inject_anchors` were incorrect, producing _links to anchors_ instead of anchors. I fixed this by patching the plugin `lib/table_of_contents/parser.rb` replacing the `href` attribute with `name="#{entry[:id]}"`.

## Useful Theme options

- Javascript with slash-comments will break if compressed using standard simple newline removal. For some reason the `compress_html` option includes Javascript files. Excluding all `.js` files fixes the issue.
```yml
jekyll_tidy:
  compress_html: true
  exclude: ["*.js"]
```

- Set `has_children: true` to (1) show the page's child pages in the site nav and (2) show child pages as a table of contents. Set `has_toc: false` to remove the section table of contents from the page.

- Set `nav_enabled: false` to remove the main menu from the left side of a page.

## Site Structure

We're aiming for a friendly user manual style with a clear hierarchy of sections and pages. We're sorting out sections as we go along. Large sections present the most challenge. They need to be decomposed and organized carefully to ensure the user has context for all the articles.

For G-code we need indexes in a few different forms. We need a numerical index so the user can find the G-code by name quickly and click to it.

We need Features to be organized into sections based on the `@section` annotations in the Configuration files. Sometimes these correspond to the G-code sections in the source, but not always.

Each display that Marlin supports can have a page with a description of the display, its features or "stats", and how to configure it. We can link to these pages from the G-code and Feature pages that relate to them. For some displays we can display a 3D interactive model of the display, just for fun.

These large areas of the documentation cannot have links for everything within on the left side. At most we can list the sections.
